# Tower Front 3.0 검증 기록

## 자동 검사
- TDD: FinalEngineTest와 ControlsTest를 먼저 작성하고 구현 누락으로 실패하는 것을 확인한 후 구현했습니다.
- 100% 출병 시 병력 1명 전송 회귀 검사도 실패를 먼저 확인하고 수정했습니다.
- `pytest tests/test_tower_front.py -q`: 통과. 4개 Java 테스트 묶음(EngineTest, PhaseTwoTest, FinalEngineTest, ControlsTest)을 컴파일·실행합니다.
- 검사 범위: 출병/증원/점령/승패, 이동 병력 생존 판정, 생산·기동 타워, 강화 비용과 생산 배율, 캠페인 범위, 난이도, 별 기록, 저장/정확한 복원/결정적 재개, 잘못된 저장값 및 터치 입력.
- 잘못된 저장 검사는 NaN 좌표, 병력 범위, 타워 수 불일치, 이동 병력 인덱스, 추가 바이트, 잘린 데이터와 잘못된 Base64를 포함합니다.
- Lizard: Java 소스·테스트 함수 50줄 이하 및 복잡도 10 이하. 경고 없음.
- Radon: 빌드 도구 복잡도 A(1–2), pytest 실행기 A(4).
- `pytest tests -q`: 293개 통과, 기존 `test_web_plan_features.py::test_web_plan_runtime_behavior` 1개 실패. 웹 기능 파일은 이번 작업에서 수정하지 않았습니다.

## Android 15(API 35) 실행 검증
공식 AOSP x86_64 시스템 이미지를 사용한 400×900 가상 기기에서 확인했습니다.
- 기존 v2 APK 설치 후 같은 서명으로 v3 업데이트 설치 성공.
- 시작 화면, 난이도별 작전 목록, 전장, 일시정지와 설정 화면을 캡처하여 확인.
- 아군 선택 후 목표 터치로 실제 병력 출병 확인.
- 이동 중인 병력이 있는 전투 저장 후 강제 종료·재실행: 저장 데이터 정확히 유지.
- 전투 중 홈으로 나갔다 복귀: 자동 일시정지 화면 확인.
- 효과음·진동을 끄고 강제 종료·재실행: 설정 유지 확인.
- 승리 직전 상태를 가상 기기에 주입하여 별 3개 지급과 다음 작전 해금을 확인.
- 마지막 작전 승리 직전 상태를 주입하여 캠페인 완료 화면과 작전 지도 버튼 확인.
- AndroidRuntime 오류 로그 없음.

## 범위
실제 휴대폰, Android 8–14 기기별 화면·소리·진동, 모든 작전의 사람 플레이 밸런스는 검증하지 않았습니다.
가상 기기의 결과 화면 검증에는 테스트 전투 상태를 사용했으며, 실제 12개 작전을 모두 플레이하여 승리했다는 의미는 아닙니다.
앱 배포 파일에는 테스트 상태나 테스트용 진입점을 포함하지 않습니다.

- EffectsTest를 먼저 작성하여 구현 누락 실패를 확인하고 구현. 5개 Java 회귀 테스트 묶음 통과.

- Android15 가상 기기에서 타격 -16 / 증원 +10 / 점령을 동시에 표시하는 장면과 승리 축하 입자를 캡처·확인.
- Lizard 함수 50줄·복잡도10 제한 경고 없음. APK 빌드·서명 검증 통과. QA 검토 지적 수정 완료.
- 효과음의 실제 음질은 확인하지 않았습니다.

## 뒤로 가기 오류 수정
작전 지도에서 뒤로 가기가 앱 종료로 이어지는 문제를 Android15 실행 검사로 재현하고 수정했습니다.
전투에서는 뒤로 가기 1회로 일시정지, 다시 누르면 시작 화면으로 돌아갑니다.
`tools/check_navigation.py --serial emulator-5580`으로 작전 지도 복귀, 전투 일시정지, 메뉴 복귀 시 저장 상태 유지, 이어하기를 확인했습니다.
이 검사는 기존 저장 전투가 있는 루트 AOSP 가상 기기에서 실행합니다. QA 검토 완료.
