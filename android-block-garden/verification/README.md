# 1.2.1 게임 규칙 및 클리어 검증

총 100단계를 단계당 300번, 합계 30,000번 자동 플레이했습니다. 모든 단계에서 최소 1개의 합법적인 클리어 경로를 확인했습니다.
실제 Engine.place를 사용해 블록 3개 지급, 중복 배치 차단, 세 패 소진 후 재지급, 미션 횟수 제한을 적용했습니다. 회전이나 블록 교환은 사용하지 않았습니다.
각 단계의 첫 성공 경로를 winning-moves.csv에 기록하고 새 엔진으로 재생하여 패의 연속성, 배치 가능 여부, 제한 횟수, 최종 미션 성공을 확인했습니다.
results.csv 열: stage, 성공 횟수, 시도 횟수, 첫 성공 seed, 첫 성공 배치 횟수. 마지막 줄은 전체 성공 단계 수입니다.
winning-moves.csv의 좌표는 0부터 시작하며 블록/슬롯 번호는 Playability.java에 대응합니다.

97단계는 300번 중 1번, 93단계는 4번, 89단계는 6번 성공했습니다. 이 수치는 단순 자동 플레이 전략의 성적이며 사람의 성공 확률을 의미하지 않습니다. 모든 무작위 패가 클리어 가능하다는 보장도 아닙니다.
난수 seed는 자동 플레이 프로그램 기준입니다. 앱은 색상 생성에도 난수를 사용하므로 앱에서 같은 seed만 입력하여 재현할 수 없습니다. 실제 패와 좌표를 CSV로 보존했습니다.

수정: 저장된 별 문자열에 0/1 이외의 문자가 있으면 목표가 사라져 자동 클리어되는 문제를 막았습니다. 잘못된 별 데이터는 해당 단계의 초기 목표로 복구합니다.
엔진·미션·저장 데이터 pytest, Java 함수 길이/복잡도 검사, APK v2/v3 서명 검증을 통과했습니다.
실제 Android 기기 화면·터치·모드 전환·저장소 실행 검증은 수행하지 못했습니다. 정상 저장 데이터 기준 추가 진행 차단 오류는 코드 검토에서 발견하지 못했습니다.

재실행: JDK로 src/com/blockgarden/Engine.java, Mission.java와 tests/Playability.java를 함께 컴파일하고 com.blockgarden.Playability에 출력 CSV 경로 인수 하나를 전달합니다.
